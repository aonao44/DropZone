【STEP 0】 対象ファイルの特定とリセット
プロジェクト内にある 「クライアント用の素材提出フォーム（Submission Form）」 のコンポーネント（components フォルダ内にある、提出用 UI のメインファイル）を特定してください。 特定した既存ファイルの中身を全面的に書き換え、以下の要件に基づいた新しい「ツーペイン仕分け UI」を実装してください。 ※ 新しいファイルを作成せず、必ず特定した既存のコンポーネントファイルを編集すること。

【STEP 1】 UI レイアウト要件 (Split-Pane)
画面を「アップロードエリア（上部）」と「仕分けエリア（下部）」に分け、仕分けエリアは 左右（スマホは上下）の 2 カラム構成 としてください。

A. 左カラム: Inbox (未振り分け)
役割: ドロップされた直後のファイルを一時保管する場所（Staging Area）。

必須機能:

複数選択: Shift + Click (範囲選択) および Ctrl/Cmd + Click (個別選択) に対応。

全選択: ヘッダーに「すべて選択」ボタンを配置。

ドラッグ操作: ここから右カラムへドラッグ＆ドロップで移動可能にする。

B. 右カラム: Targets (依頼スロット一覧)
役割: プロジェクトで定義された各スロット（ロゴ、メイン画像など）のリスト。

必須機能:

各スロット自体も DropZone として機能させる。

コメント機能: 格納されたファイルの横に吹き出しアイコンを置き、クリックで「申し送り事項」を入力可能にする。

ステータス表示: 「必須/任意」「残り枚数」「完了」などを可視化。

【STEP 2】 挙動・インタラクション要件

1. ハイブリッド・ドロップ操作
   ユーザーが以下のどちらの操作を行っても正しく処理されるようにしてください。

パターン A (仕分け): Inbox(左)に一度入れてから、Targets(右)へドラッグして割り当てる。

パターン B (直入れ): デスクトップから直接 Targets(右)のスロットへドロップし、即時割り当てる。

2. 再提出とバージョン管理 (v2)
   既にファイルが存在するスロットに新しいファイルが追加された場合、上書きではなく「新しいバージョン」として処理してください。

UI 上では最新のファイルをサムネイル表示し、目立つ色で NEW または v2 バッジ を付与してください。

内部的には既存ファイルを削除せず、DB へは新規レコードとして Insert するロジックとしてください。

3. モバイル対応 (Responsive)
   画面幅が狭い場合 (sm, md 以下) は、左右カラムを 「上下配置 (Stack)」 に切り替えてください。

モバイル時はドラッグ操作を無効化（または補助）し、「Inbox でファイルをタップ選択」→「対象スロットボタンをタップ」 というクリックベースの移動 UI を提供してください。

4. フィードバック (Progress)
   アップロード処理中は、各ファイルのサムネイル下に必ず プログレスバー またはローディングスピナーを表示し、フリーズしていないことを明示してください。

【STEP 3】 技術的制約 (Technical Constraints)
コードの品質と保守性を保つため、以下の構成を守ってください。

コンポーネント分割: 1 つのファイルに全コードを書かず、適切な粒度でサブコンポーネントに分割してください。

例: InboxColumn, TargetSlotList, DraggableFileCard など

ライブラリ選定:

Drag & Drop 機能には @dnd-kit/core (推奨) または標準 API を使用し、軽量かつ堅牢に実装してください。

既存資産の保護:

useSlots などの既存フックや、app/api/ 以下のバックエンドロジックは破壊せず再利用してください。

DB スキーマ (project_slots, slot_files) の変更は行わないでください。

# 要件定義書：DropZone（仮）

**〜 コミュニケーションコストをゼロにする、素材管理・検品 SaaS 〜**

**Version:** 1.0  
**Status:** Draft

---

## 1. プロジェクト概要

### 1.1 目的

クライアント（店舗オーナーなど）と制作者（構築者・デザイナー）の間で発生する「素材回収」の非効率（画像の散逸、画質の劣化、言った言わない問題）を解消する。
チャット機能を持たず、**「提出」→「検品（OK/NG）」→「納品」**のステータス管理に特化することで、IT リテラシーの差によるトラブルを防ぐ「デジタル検品所」を構築する。

### 1.2 ターゲットユーザー

- **ホスト（課金ユーザー）：** Shopify 構築者、Web ディレクター、小規模制作会社
- **ゲスト（無料ユーザー）：** 店舗オーナー（クライアント）、デザイナー

---

## 2. ユーザーロール（権限）定義

| ロール    | 名称             | 役割                     | 可能なアクション                                                  |
| :-------- | :--------------- | :----------------------- | :---------------------------------------------------------------- |
| **Admin** | ホスト（管理者） | プロジェクト作成・検品者 | PJ 作成、招待 URL 発行、**素材の承認/差戻し**、強制削除、設定変更 |
| **User**  | ゲスト（提出者） | クライアント             | 素材アップロード、自身の素材削除（承認前のみ）、NG コメントの確認 |

---

## 3. 業務フロー（ユースケース）

1.  **PJ 作成:** ホストがプロジェクトを作成し、招待 URL を発行する。
2.  **共有:** ホストが LINE やメールでゲストに URL を送る（ログイン不要、または簡易認証）。
3.  **提出:** ゲストが画像をドラッグ＆ドロップでアップロードする。
    - _システム挙動:_ 自動でステータスを「🟡 確認待ち」にする。
4.  **検品:** ホストが管理画面でサムネイルを確認。
    - **OK の場合:** 「✅ 承認」ボタン押下 $\to$ ステータス「🟢 確定」へ（ロック）。
    - **NG の場合:** 「↩️ 差戻し」ボタン押下 $\to$ **修正指示コメントを入力** $\to$ ステータス「🟣 リテイク」へ。
5.  **修正:** ゲストに「修正依頼」の通知が届く。再アップロードを行う。
6.  **完了:** 全ての素材が「🟢」になったら、ホストが一括 DL して終了。

## 4. 機能要件詳細

### 4.1 プロジェクト管理（ダッシュボード）

- **プロジェクト一覧表示:** 作成した案件をカード形式で一覧表示。
- **進捗バー:** 「全 10 ファイル中 8 ファイル完了」のような視覚的な進捗表示。
- **ステータスフィルター:** 「未完了の案件」だけを表示する機能。

### 4.2 素材アップロード機能（ゲスト画面）

- **Drag & Drop:** 直感的なアップロード領域の実装（DropZone）。
- **対応フォーマット:** JPG, PNG, GIF, WEBP（動画 MP4 は要検討だが MVP では画像優先）。
- **バリデーション:** 容量制限（例: 1 ファイル 20MB まで）、枚数制限（プランによる）。

### 4.3 検品・ステータス管理機能（**最重要**）

- **サムネイル生成:**
  - アップロードされた画像をリサイズし、一覧画面で**視認可能なサイズ（例: 150px 角）**で表示する。
  - クリックでオリジナル画像（または拡大プレビュー）をモーダル表示。
- **ステータスボタン:**
  - 各行（カード）に**「✅ 承認（Approve）」「↩️ 差戻し（Reject）」**ボタンを配置。
  - 承認時：行全体が緑色に変化などの UI フィードバック。
- **NG コメント入力（ポップオーバー）:**
  - 差戻しボタン押下時のみ、テキストエリアを表示。
  - 入力必須とする（無言 NG を防ぐため）。

### 4.4 通知・コミュニケーション機能

- **メール通知:**
  - ホストへ：「素材が提出されました」
  - ゲストへ：「素材が承認されました」「修正依頼があります（＋コメント内容）」
- **チャット機能の排除:**
  - 「お世話になっております」等の雑談チャット機能は**実装しない**。あくまでステータス変更の通知のみ。

### 4.5 ダウンロード機能

- **個別ダウンロード:** 各ファイルのオリジナルデータを DL。
- **一括ダウンロード（プレミアム）:**
  - プロジェクト内の承認済みファイルを ZIP 圧縮して DL。
  - **自動リネーム:** ファイル名を整理（例: `01_main-visual.jpg`）するオプション（将来実装）。

### 4.6 ブランディング（ホワイトラベル / 松プラン）

- **ロゴ差し替え:** ヘッダーの「DropZone」ロゴを任意の画像に変更可能。
- **ドメイン設定:** `share.dropzone.com` ではなく `assets.my-agency.com` 等で運用可能（CNAME 利用）。

## 5. 画面構成リスト（UI）

1.  **ダッシュボード（ホスト用）:**
    - 案件一覧、プランステータス表示。
2.  **プロジェクト詳細・検品画面（ホスト用）:**
    - サムネイル付きファイルリスト。
    - 各ファイルの OK/NG 操作パネル。
3.  **アップロード画面（ゲスト用）:**
    - 極めてシンプルな提出フォーム。
    - 履歴・ステータス確認エリア（NG コメント閲覧用）。
4.  **設定画面:**
    - プラン変更、ホワイトラベル設定。

---

## 6. 非機能要件

- **パフォーマンス:** サムネイル表示は高速であること（CDN 利用や画像圧縮処理）。
- **画質保持:** ダウンロード時は、アップロードされた元データを**無劣化**で渡すこと（Notion/LINE との差別化）。
- **セキュリティ:** ゲスト用 URL には有効期限または複雑なトークンを持たせ、第三者のアクセスを防ぐ。
- **モバイル対応:** クライアント（ゲスト）はスマホからアップロードする可能性が高いため、ゲスト画面は完全レスポンシブ対応必須。

## 8. 開発フェーズ（MVP ロードマップ）

### フェーズ 1：基本検品サイクル（β 版）

- 素材アップロード
- サムネイル生成・表示
- OK / NG ステータスボタンの実装
- 個別ダウンロード

### フェーズ 2：コミュニケーション完結

- NG 時のコメント入力機能
- メール通知（提出・差戻し）
- スマホレスポンシブの最適化

### フェーズ 3：マネタイズ実装

- 決済機能（Stripe 等）
- ZIP 一括ダウンロード
- ホワイトラベル機能（ロゴ差し替え）
